# Scout Development Improvements

Find one evidence-fitted opportunity for a step change. Avoid technology lists and avoid installing anything in proposal mode.

## Workflow

1. Select one opportunity from a Groundloop reflection, an active operational lesson, current repository evidence, or an explicit user question.
2. State the desired improvement, current constraint, and evidence that the opportunity matters.
3. Check installed skills, scripts, tests, platform capabilities, and project conventions before suggesting something new.
4. Research current options through official documentation and primary technical sources. Verify time-sensitive claims.
5. Compare `adopt`, `integrate`, `extend`, `build`, and `learn` paths.
6. Recommend one path and at most two credible alternatives.
7. Define a small reversible experiment with expected value, cost, success signal, stop condition, and review date.
8. Produce a self-contained HTML proposal. Do not install tools, create services, or modify the workspace without explicit authorisation.

Read [proposal-rubric.md](references/proposal-rubric.md) before ranking options or writing the experiment.

## Output contract

- Opportunity and supporting evidence.
- Why it could create a meaningful improvement.
- Recommended skill, technology, practice, or learning topic.
- Fit with the current project and workflow.
- Existing capability reused, consolidated, or replaced.
- Bounded experiment and measurement.
- Cost, risks, and exit path.
- Review date.

An evidence-backed recommendation to do nothing is valid.
