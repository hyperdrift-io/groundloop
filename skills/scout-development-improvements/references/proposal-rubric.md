# Improvement proposal rubric

Score only enough to distinguish the options. Use `low`, `medium`, or `high`; false precision is not useful.

| Dimension | Question |
|---|---|
| Mission fit | Does it make sessions more current, relevant, cumulative, or measurably better? |
| Evidence strength | Is the opportunity visible in repeated work, a severe incident, or a measured constraint? |
| Reuse | Does it extend an existing capability before creating another one? |
| Reach | How many recurring tasks or developers could benefit? |
| Time to evidence | Can a useful signal be produced in days rather than months? |
| Maintenance | Is ongoing cost comfortably below conservative expected savings? |
| Reversibility | Can the experiment stop without leaving workflow debt? |
| Privacy and trust | Does it minimise captured data and preserve user control? |

Recommend the smallest experiment that can disprove the idea. State:

- hypothesis;
- participant/task scope;
- baseline and treatment where practical;
- success and failure signals;
- maximum time/cost;
- stop condition;
- review date and owner.

Do not recommend a new skill when a test, script, existing skill update, short reference, or learning exercise is the better destination.
